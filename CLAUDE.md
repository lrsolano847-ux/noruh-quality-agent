# Noruh Quality Agent — Session Handoff

## What this project is

A fully local, offline AI quality analytics agent for **Noruh Manufacturing**,
which produces premium modular stainless steel end tables (Top, Leg, Stand).
The agent diagnoses manufacturing root causes by querying a synthetic 5-year
production database and presenting results in an Ishikawa fishbone framework.

Target environment: consumer laptop, CPU-only, fully offline.
Core stack: Streamlit · DuckDB · ChromaDB · LangGraph · Ollama.

## Current state — what is done

### Module 1: pipeline.py ✅
- Generates 5 years of factory history into `data/noruh_quality.db` (DuckDB)
- ~1.5 M rows across 4 tables: `cnc_telemetry`, `lab_testing`,
  `packaging_log`, `customer_feedback`
- 5 injected anomalies with exact PRD math — all verified:

| Anomaly | Description | Signal |
|---------|-------------|--------|
| ANOM-01 | Machine B calibration drift Apr–Jun 2022 | Dimensional deviation ramps 0.01→0.25 mm |
| ANOM-02 | Cheap tooling campaign Jun–Aug 2023 | Ra 2.4× baseline across all machines |
| ANOM-03 | New operator OP-007 gouge events Oct 2024 | 76 FAIL_GOUGE parts at 6% rate |
| ANOM-04 | Continuous tool-breakage inline scrap | 1,277 rejections (vibration > 3.5 g) |
| ANOM-05 | PKG-003 missing hardware Nov 1–14 2025 | 64 Missing Hardware claims at 8% rate |

- Generation time: ~80 s on CPU (vectorised numpy)
- Run with: `python pipeline.py`

### Module 2: database.py ✅
- `NoruhDB.execute_sql()` — read-only DuckDB queries with sqlglot AST
  injection guard (blocks DROP/DELETE/ALTER/INSERT/UPDATE/TRUNCATE)
- `NoruhDB.build_vector_store()` — embeds 10,838 customer feedback texts
  into ChromaDB using `bge-small-en-v1.5` (falls back to TF-IDF with
  persisted vectorizer at `chroma_db/tfidf_vectorizer.pkl` if offline)
- `NoruhDB.semantic_search()` — cosine similarity retrieval
- `NoruhDB.schema_info()` — table/column reference for LLM system prompt

### Module 3: agent.py ✅
- LangGraph state machine with 4 nodes:
  `tool_caller` → `tool_executor` → `critic` → `ishikawa_formatter`
- **Sequential model loading** via `keep_alive=0` (evicts each model
  after its call — keeps peak RAM within 12 GB constraint)
- `qwen3-coder:7b` — tool-calling engine (SQL generation + semantic search)
- `deepseek-r1:8b` — refining thinking engine (reads `<think>` blocks,
  issues SUFFICIENT/INSUFFICIENT verdicts)
- Max 3 self-correction passes per request
- Output: `IshikawaAnalysis` Pydantic model with 4 fishbone categories
- `NoruhAgent.stream()` yields typed events for Streamlit rendering
- `check_ollama()` validates models are pulled before UI activates

**Prompts were tuned in the last session** (fa1348c). Key improvements:
- Tool-caller: explicit Phase 1/2 contract, DuckDB SQL rules, worked example
  query, filled-in `<ishikawa>` JSON example with all 6 required keys
- Critic: 4 explicit SUFFICIENT criteria, separate tag format examples for
  each verdict, schema-aware recommended queries, empty-Ishikawa guard

### Module 4: app.py ✅
- Streamlit dashboard with sidebar (DB/Ollama/vector store health chips,
  5 example questions, conversation clear)
- `st.status()` streaming container showing: live SQL, row count previews,
  critic review expanders, final Ishikawa cards
- Ishikawa rendered as 2×2 colour-coded card grid:
  Machine (red) · Material (orange) · Method (blue) · Human/Env (green)
- Conversation history persists within session

### Test infrastructure ✅
- `mock_ollama_server.py` — local HTTP server on `localhost:11434` speaking

- `test_agent.py` — runs all 5 anomaly investigations through the full

## How to run locally (user's machine)

```bash
cd noruh-quality-agent
pip install -r requirements.txt

# One-time: generate the database (~80 s)
python pipeline.py

# One-time: pull Ollama models (~8 GB total)
ollama pull qwen3-coder:7b
ollama pull deepseek-r1:8b

# Launch the app
streamlit run app.py
```

The vector store (`chroma_db/`) is built automatically on first app launch.

## Key design decisions already made (do not revisit without user input)

| Decision | Rationale |
|----------|-----------|
| Sequential model loading (`keep_alive=0`) | Keeps peak RAM ≤ 12 GB on 16 GB machines |
| TF-IDF fallback for embeddings | Allows testing in network-isolated envs; production uses bge-small-en-v1.5 |
| sqlglot AST + regex dual guard | AST catches embedded mutations; regex catches edge cases |
| 3-pass retry limit | PRD requirement; prevents infinite loops |
| `data/` and `chroma_db/` gitignored | Runtime artifacts, regenerated by pipeline.py / database.py |
